# Ariadne v0.5 设计：领域调研

日期：2026-08-29
状态：设计待确认
上游：[v0.4 台账界面与闭环补全](2026-08-27-gui-v0.4-design.md) · [领域规则](2026-08-23-experiment-loop-design.md)

## 1. 版本目标

现在的管线从**想法**开始：

```
想法 → 批次（预测 → 结果 → 判定 → 复盘） → 信念 → 论文
```

但想法不是凭空来的。它来自"我搞清楚了这个领域现在卡在哪"。v0.5 把这一段补在前面：

```
调研（分层阅读 → 领域地图 → 瓶颈陈述） → 想法 → 批次 → 信念 → 论文
```

**这一段是可跳过的**——不是每次开工都在进新领域。但它必须存在，否则想法那一页永远是个空文本框，而"从哪来"这个问题系统一句话都没说。

完成标准：给一句话主题，能在几分钟内拿到一张分层的阅读清单——**该你亲自精读的十来篇**，和**AI 替你摘要的长尾**——读完之后写下一句"这个领域卡在哪"，一键变成想法立项。

## 2. 这不是引文管理器

Zotero 已经存在，而且在存 PDF、管 BibTeX、插引用这些事上比我们能做的好得多。**不要重做它。**

这一层只做 Zotero 不做的两件事：

1. **分配你的注意力。** 一个新领域有几百篇论文，你的时间只够精读十几篇。哪十几篇？这是个可以算的问题，不该靠感觉。
2. **以一句瓶颈陈述结束。** 调研不是为了拥有一个文献库，是为了产出一个能做的实验。不落到这句话上，前面读的全白读。

所以本版**不做**：PDF 存储、BibTeX 导入导出、引用格式化、全文检索。

## 3. 数据源：OpenAlex

以下全部对着 `api.openalex.org` 实测核实过，不是凭记忆写的。

**不需要 API key。** 直接 GET 即可。

**限流是信用点制，不是"每天 N 次"。** 响应头给出预算：

```
x-ratelimit-limit: 1000
x-ratelimit-remaining: 980
x-ratelimit-reset: 71829        # 秒，约 20 小时
x-ratelimit-cost-usd: 0.001
```

一次「取 25 篇近期论文 + 每篇的 referenced_works」花 **10 点**。1000 点的池子够跑约 100 次这样的检索。对单人本地工具完全够用，但**界面必须显示剩余额度**，并在 429 时按 `Retry-After` 退避——不能让用户面对一个没有解释的失败。

**稳定标识是 OpenAlex Work ID，不是 DOI。** 实测：Dropout 那篇 JMLR（`W2095705004`）在 OpenAlex 里 `doi` 是 `null`。`ids` 字段里有 `openalex` / `doi` / `mag`，**arXiv ID 不保证存在**（Attention Is All You Need 就没有）。所以主键用 `W...`，DOI 与其余 ID 作为附属信息存下来。

**摘要只有倒排索引，没有原文字段。** `abstract_inverted_index` 是 `{词: [位置...]}`，要自己还原：

```python
def reconstruct_abstract(inverted: dict) -> str:
    at = {i: word for word, positions in inverted.items() for i in positions}
    return " ".join(at[i] for i in sorted(at))
```

实测 Attention 那篇还原出 1136 字符的完整摘要，足够做摘要与"它改了什么"的判断。

**`referenced_works` 可以批量取**，实测平均每篇 40 条，这是分层算法的输入。

礼貌起见在 `User-Agent` 里带 `mailto:`，从 `config.toml` 读（不带也能用，实测额度一样）。

## 4. 分层：里程碑是算出来的

**关键决定：不问 LLM 哪些是里程碑论文。**

理由与"AI 不给数值"完全同构，但更严重。一个编造的数值你跑一次实验就发现了；一个编造的引用会跟着你进 related work，直到审稿人指出来。而且"里程碑"这件事本来就不该问 LLM——引用图数据是可核实、可复现的，正好对应本项目那条原则：结论必须纯离线可复现。

### 4.1 内部被引

```
种子集 S = OpenAlex 按主题检索、限定近 N 年、取前 K 篇（默认 K=50）
内部被引(w) = S 中引用了 w 的论文数
里程碑 = 内部被引 ≥ max(3, 15%·K) 的 w，按内部被引降序
长尾   = S 本身
```

读法：**"这个子领域的近期工作里，有 7/25 篇都引了它"**——这比原始被引数好，因为原始被引数受领域规模影响极大，一篇平庸的综述可能比奠基工作被引更多。

已在真实数据上验证：以 "dropout regularization overfitting" 取 2023 年后 25 篇，内部被引最高的正是 Dropout 那篇 JMLR 原文（7/25）。算法找对了。

### 4.2 分层可以人工改

算法给的是起点，不是判决。你可以把任何一篇拉进里程碑或推回长尾，改动记为 `paper_tiered` 事件（`by: manual`）。你比算法更懂你在找什么。

### 4.3 检索式存档

主题 → 检索式这一步由 AI 做（你可以改），**但检索式本身存进 `survey_opened` 事件**。半年后你想知道"我当初到底搜了什么"，答案在账本里，而且可以原样重跑。

## 5. AI 的角色：受限，且与预测层同构

**AI 绝不产出论文条目。** 所有条目来自 API，每一条都带 `W...` ID，可点开核实。这是结构保证，不是提示词里的一句请求——schema 里根本没有让模型自由填写标题的字段。

AI 只做三件它真正擅长的事：

| 时机 | 做什么 | 输入 |
|---|---|---|
| 开调研 | 一句话主题 → OpenAlex 检索式 | 你的主题描述 |
| 长尾分层之后 | 每篇"它相对于里程碑改了什么" | 真实摘要原文 |
| 你写完瓶颈之后 | 一份独立的瓶颈判断 | 地图 + 你的陈述 |

第三条完全复用预测层的锚定规则：**你先写你认为的瓶颈，写完才能看 AI 的。** 先看 AI 的判断，你自己的分析就失去了独立性——而独立性正是这套机制价值的来源。不一致的地方是信号。

## 6. 诚实性：AI 摘要不等于我读过

这一层的核心风险不是幻觉，是**自欺**：读了 40 篇 AI 摘要，三个月后记成"我调研过这个领域"。

所以这是结构保证，不是界面上一个标签：

| 事实 | 事件类型 |
|---|---|
| 我精读了这篇，拿走了这个 | `paper_read`，payload 里有 `takeaway` |
| AI 替我摘要了这篇 | `note`，`kind: "ai_paper_summary"` |

`note` 事件本来就被所有投影跳过、不参与任何判定——v0.4 的 AI 层已经建立了这个约定。摘要落在 `note` 里，**"读过"这个状态在数据层面就不可能被 AI 写入**。

界面上同样分开：里程碑那一栏显示"待精读 / 已精读 + 你的一句话收获"，长尾那一栏显示"AI 摘要"。精读笔记必填一句"这篇给了我什么"——和预测必填理由是同一个道理：不写下来，等于没读。

## 7. 事件模型

新增类型，注册进 `_KNOWN_TYPES`，由独立模块 `surveys.py` 投影（与 `ideas.py` / `beliefs.py` / `papers.py` 同构，不进 `project.py` 的批次投影）：

```
survey_opened      { topic, question, query, source: "openalex", k, years }
paper_found        { work, title, authors, year, venue, cited_by, in_set, abstract, ids }
paper_tiered       { work, tier: "milestone"|"followup", by: "auto"|"manual" }
paper_read         { work, takeaway }
paper_skipped      { work, reason }
survey_bottleneck  { text }
survey_closed      { }
note               { kind: "ai_paper_summary", work, summary }
note               { kind: "ai_bottleneck", bottleneck }
```

调研 ID 与批次同构：`s1`、`s2`……（`next_survey_id`）。

`paper_found` 把抓到的元数据**整条存进事件流**。理由：断网之后调研页照常可用；OpenAlex 改了数据也不影响你当时看到的东西；而且这是唯一真相来源那条原则的直接推论。

## 8. 信息架构

导航从四项到五项，正好是研究管线的顺序：

```
今天   调研   批次   账本   论文                              ⌘K
```

调研页（台账样式，与批次页同构）：

```

  7/50 引用   Batch Normalization…                   2015   待精读 →
  5/50 引用   mixup: Beyond Empirical Risk Minim…    2018   待精读 →
────────────────────────────────────────────────────────────────
长尾（41） —— AI 摘要，先不精读                        全部摘要 →
  2024  Revisiting Dropout for Small-Scale…    改了什么：把 dropout 率
        按层深退火，其余照搬 2014 的设置
  2023  Augmentation Schedules Under Budget…   改了什么：只动增强强度
        的时间表，模型容量固定
────────────────────────────────────────────────────────────────
```

今天的待办清单增加两种行：

- **待精读** —— 里程碑里还没读的（排在等结果之后、可收口之前）
- **待写瓶颈** —— 里程碑都读完了，该收口了

## 9. 收口：调研 → 想法

调研以一句瓶颈陈述结束，旁边一个「立为想法」——复用现有的 `idea_captured`，payload 里带 `survey` 引用。想法页与批次页因此能一路回溯到"这个念头是从哪篇论文的哪个缺口来的"。

论文草稿的素材选择器增加一类：**调研**。引用一个调研，展开成里程碑清单与你的精读笔记——related work 那一节的原始材料本来就是这些。

## 10. 离线与降级

与 LLM 层同构，两种失败都不阻断：

| 情况 | 行为 |
|---|---|
| 断网 / OpenAlex 不可达 | 调研页照常显示已抓到的一切（都在 `runs.jsonl` 里），只是抓不了新的。一行安静的说明。 |
| 额度用尽（429） | 显示 `Retry-After` 换算出的时间，不重试轰炸 |
| 没配 LLM | 检索式要你自己写，摘要那一栏空着，瓶颈只有你自己写的那份。其余照常。 |

## 11. 不做什么

- **不做引文管理器。** 见 §2。不存 PDF、不导 BibTeX、不管引用格式。
- **不读全文 PDF。** 这一版只用标题与摘要——足够回答"值不值得精读"和"它相对于那篇改了什么"，不足够回答"它的实验怎么做的"。后者本来就该你自己读。
- **不让 AI 产出论文条目。** 见 §5。
- **不做多数据源。** 先只 OpenAlex。arXiv / Semantic Scholar 等以后再说，`source` 字段已经预留。
- **不做引用图可视化。** 一张漂亮的关系图不会让你多读一篇论文。内部被引数那一列已经说清了同样的事。

## 12. 测试

`surveys.py` 的投影与分层算法是纯函数，测试覆盖重点：

- 内部被引计数与阈值（含 K 很小、无重叠引用等边界）
- 人工改层覆盖自动分层，且顺序无关
- `abstract_inverted_index` 还原（含空、含缺位）
- `paper_read` 与 `ai_paper_summary` 互不影响：摘要过的论文不会因此变成"已读"
- 瓶颈未写时拒绝给 AI 判断（锚定约束，与 `ask_advice` 同一条）

碰网络的只有 `openalex.py` 的 `search()` 一个函数，测试不调它——与 `llm/claude.py` 的 `request()`、`editor.py` 的 `$EDITOR` 是同一个结构。限流头解析、检索式构造、结果归一化都是纯函数，用 fixture 测。
